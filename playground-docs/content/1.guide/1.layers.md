---
title: Layers
description: How an app uses the layers of yuri4n.dev.
---

Each layer is a pnpm workspace package with `"main": "./nuxt.config.ts"`.
An app extends the layers it wants, by package name:

```ts
export default defineNuxtConfig({
  extends: ['@yuri4n/nuxt-base', '@yuri4n/nuxt-ui'],
})
```

The same `extends` line works when the packages come from npm later.

## App layers

`@yuri4n/nuxt-base`, `@yuri4n/nuxt-ui` and `@yuri4n/nuxt-content` do not
extend each other. The app lists the ones it needs. The library tests them
together in `playground/`.

## Docs layers

`@yuri4n/nuxt-docs` extends Docus. `@yuri4n/nuxt-docs-exdoc` extends
`@yuri4n/nuxt-docs`, because it cannot work alone. This site extends the
exdoc layer, so it tests both. Docus owns the routing and imports Tailwind
itself, so the docs layers cannot share an app with the ui layer. That is
why the library has two playgrounds.

## Hooks

A layer exposes hooks instead of a skin: CSS variables, `app.config` keys,
slots and Nuxt runtime hooks. The docs layer, for example, calls the
runtime hook `docs:linkify-fence` after a code fence renders, and the exdoc
layer listens to it.
